HLB LOAD$  ·  Disbursement (Batch 3)

PROTOTYPE WALKTHROUGH
=====================

A short guide to what the prototype covers and how to move through it. It
describes the paths, not the rules — the functional specification remains the
reference for detail.


BEFORE YOU START
----------------

  File      HLB_放款原型_合并版.html — one file, nothing to install
  To open   Double-click it. Chrome or Edge is recommended.
  Network   Not required. It runs entirely in the browser.
  Build     Shown at the top right of the screen,
            e.g. "Prototype build 2026-08-30"

  - Everything you see is sample data. Nothing is saved and nothing is sent
    anywhere.
  - Refreshing the page resets it to the starting state, so you can explore
    freely.
  - The dark strip along the top is a demo toolbar. It lets you switch role
    and scenario so one file can show several situations. It is not part of
    the product.


WHAT IS IN IT
-------------

Three entries, connected the way they will be in the product:

  CRA Workbench     where CRA reviews the case summary, checks the rules,
                    works the defect list, maintains disbursement information
                    and submits the case.

  Sales Workbench   the same defect list, seen from the other desk. Sales
                    cannot conclude rules or close defects; each row offers
                    the one thing Sales can do — send a document.

  File Center       where documents live. It opens in the view of whoever
                    came through: CRA sees the whole case, Sales sees the one
                    defect they clicked.

Moving between them

The three buttons in the demo toolbar switch entries at any time. In normal
use you arrive by the work rather than by the switch:

  - CRA opens it from Attachment in the top bar, from Attachment in the
    Navigation card, or from Open File Center in the Verification Summary.
  - Sales opens it from the action on a defect row.
  - Back To List, or the ✕ at the top right, returns to whichever desk
    opened it.

Which view the File Center is in is decided by that door — there is no
role or case-state switch sitting above the screen. The strip at the top
left says where you are, for example "Sales · answering defect #2".


THE MAIN PATHS
--------------

Five walkthroughs. Each takes a couple of minutes and they follow the order
of the real process.


Path 1 · Sales uploads the documents
Document Center, with the role set to Sales and the case state Sales Drafting.

  1. Choose who the documents belong to on the left — Main Applicant,
     Guarantor 1 or Seller.
  2. Two upload entries appear above the list:

       AI Scanning       read and classified automatically. The chips below
                         it name a few of the types it handles.
       Non AI Scanning   stored as-is and checked by hand. Anything outside
                         the AI list goes here.

  3. Not sure which entry a document belongs to? Click "+N more" beside the
     AI chips and search for it. The list says which entry each type takes.
  4. After upload, set the Category yourself in the File List — the entry
     does not have to guess it, and you can change it at any time while the
     case is still yours.
  5. When the documents are complete, click Submit for Verification at the
     bottom right to trigger rule validation.


Path 2 · CRA checks the rules and raises defects
Document Center, role CRA, case state CRA Review. Pick a subject on the left
to reveal the two rule tabs.

  1. Cross-Validation Results holds the rules the engine concluded on its
     own. Open a document to see its alerts.
  2. Every failing rule offers Create Defect. The dialog opens with the
     category and the defect types already filled in from the rules that
     failed on that document — Defect Type is multi-select, because one
     document rarely breaks one rule at a time.
  3. One defect per document. If the document already has one, the button
     says Update Defect: the type set is rewritten from the latest rules,
     the CRA remark is appended to, and the defect number stays.
  4. The alert stays on the file after the defect is saved. The two answer
     different questions — is this document readable, and who owes what —
     so clearing one must not clear the other.
  5. There is no defect list here. Defects are raised in front of the
     document and read in the Workbench; one ledger, not two.
  6. Manual Check Results holds documents OCR cannot read. The rules sit on
     the left, the document on the right; mark each Pass or Fail. Pass All
     concludes the page in one action, and a failing rule offers the same
     Create Defect.
  7. The bar at the bottom always shows both tracks — for example
     "OCR 13/19" and "Manual 0/6" — no matter which tab you are on.


Path 3 · Sales answers the defects
Sales Workbench.

  1. The defect list is the same list CRA sees — same rows, same columns,
     same numbers. What differs is the action: Replace Document, or Upload
     Document where the defect names no file yet.
  2. That opens the File Center on that defect alone. The strip at the top
     says which one, and the list is narrowed to it; Show all defects widens
     it again.
  3. The File Type is fixed by the defect — you are replacing a document,
     not adding one. Both upload entries stay open.
  4. If AI reads a different type than the one the defect names, it returns
     others and extracts nothing. Simulate Wrong File shows it: nothing
     changes and the file waits in the list. Swap it and upload again.
  5. Simulate Upload supersedes the file rather than modifying it. The old
     version stays retrievable with the alerts CRA saw still on it, and it
     is never removed automatically — deleting is manual and the consequence
     is yours.
  6. Choose what the re-check finds beside the upload it describes:

       a  the rule is still not solved — the defect stands as it is
       b  the rule is solved — the defect is verified on CRA submission
       c  solved, but a different rule now fails — the defect is rewritten,
          keeping its number and its remark
       d  partly solved and a new rule appears — handled the same as c

  7. Replacing a document reruns every rule in the case, not just the ones
     on that file, and the result is carried back to the workbench on its
     own. In c and d a cross-document rule also moves: it reads the replaced
     agreement as well as the second schedule, so replacing one file changes
     a rule sitting on a file nobody touched. Its defect hangs on the
     replaced document — the one that changed, and the only one Sales can
     act on next round.
  8. Return To CRA hands the case back once every defect has an answer.


Path 4 · CRA works the case
CRA Workbench. Walk Path 3 first — the state after a replacement arrives
here on its own, rather than from a switch.

  1. Verification Summary shows how many rules the case has, how many are
     concluded, and how many did not pass.
  2. View detail lists them. On the first check that is the whole set of
     failures; each one offers Create Defect, or Handle rule to settle it —
     amend the extracted value, apply a justification, or replace the
     document.
  3. After Sales sends a document back it reads differently. All rules were rerun, but only what moved
     and what sits on a replaced document is put in front of you; the rest
     keep their earlier conclusion and fold away behind Show. A rule that
     flipped on a document nobody replaced is called out separately — it is
     the reason the rerun covers the case rather than one file.
  4. Defect List carries one row per document, with the rules it covers and
     every defect type on it. A row rewritten by revalidation says so.
     Rectify, then Verify. Sync System Defects realigns the system-raised
     rows with the latest rules; rows added by hand are never touched.
  5. Add Defect is the other direction — the defect comes first and the
     document follows. It names no document type, so AI Scanning is not
     offered for it: Sales uploads straight to the file list and you read it
     by eye.
  6. Sync from OCR pulls extracted values in for comparison. A field is only
     written back from a document that is the latest version and carries no
     open defect. If either fails, the field is held back and the block says
     which defect to close — the previous version is never used as a
     fallback.


Path 5 · Submit and route
CRA Workbench. This is where the case is decided.

  1. Tick CRA Completed in the panel on the right. This is the only thing
     that enables the Next button — outstanding rules and defects do not
     block submission.
  2. Click Next. The system runs a pre-submit check, saves, assesses STP
     eligibility, then routes the case.
  3. There are three outcomes. Straight-through to disbursement; routed to
     the Authorizer; or, if the case was never an STP scenario, sent to
     Disbursement Information Maintenance for manual handling.
  4. Use Scenario and the STP switch in the demo toolbar to see each outcome
     without rebuilding the case.


WORTH KNOWING
-------------

  - The demo toolbar exists only so one file can show several situations. It
    will not be in the product. What it still carries is the entry switch,
    the STP scenario, and — inside the upload dialog — what the re-check
    finds. Role and case state are not switches any more: they follow from
    the door you came through.
  - A defect raised in the Document Center appears in the Workbench defect
    list. That is one ledger seen from two screens, not two ledgers kept in
    step.
  - Figures, names and document lists are illustrative. They are there to
    make the screens readable, not to be checked for accuracy.
  - A few areas are shown as headings without content. Those are existing
    screens that this change does not touch.
  - When sending feedback, please quote the build date shown at the top
    right so we know which version you were looking at.

Questions or comments on the prototype are welcome at any point — the paths
above are the ones we would most like reactions to.
